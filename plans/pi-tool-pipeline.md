# pi-tool-pipeline — 条件式工具编排（待办）

## 需求

- 提供独立的 pipeline 工具，由模型一次提交两个或多个现有工具调用及各自参数；不 override 原工具，也不向原工具增加 `then_run` 参数。
- 按顺序执行：仅当前一步的最终工具结果 `isError === false` 时才执行下一步；失败则跳过余下步骤，返回已执行与跳过步骤的结果。最小场景是 `edit(path, ...)` 成功后执行预先给定参数的 `bash(command)`，不要求从前一步的输入或输出构造下一步参数。
- 内部每一步都是独立的 pi 工具调用，保留该工具原有的参数校验、`tool_call` 权限拦截、`tool_result` 处理及错误语义，不能通过直接调用工具实现绕过这些边界。

## 现状

- pi 扩展可以注册新的工具；`pi.getAllTools()` 只能取得名称、参数 schema 等元数据，公开的扩展 API 没有按名称分发另一个完整工具调用、并取得其最终 `isError` 的方法。
- 在 pipeline 工具的 `execute()` 内直接调用现有工具的 `execute()`，不会自动形成独立的 pi 工具调用，也不会自动经过原有的工具事件链和最终结果判定。让模型在同一轮提交两条普通工具调用，也不能依靠当前默认并行执行保证先成功再运行后一步。
- 因此目前无法仅通过独立扩展实现上述完整语义；需要 pi 提供受控的子工具分发 API。未开始实现。
